# Каталог фильмов — техническая спецификация

## 1. Модель данных

### 1.1 Сущность "Медиа" (фильм / мультфильм / сериал)

| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Первичный ключ |
| `title` | string | Название (оригинальное) |
| `title_ru` | string | Название на русском |
| `year` | int | Год выпуска |
| `description` | text | Краткое описание/синопсис |
| `poster_url` | string | Ссылка на постер (или путь в объектном хранилище, если постер скачан) |
| `type` | enum | `movie` \| `cartoon` \| `series` |
| `category` | enum | см. п. 1.2 |
| `cartoon_subtype` | enum, nullable | см. п. 1.3, заполняется только если `type = cartoon` |
| `genres` | string[] | Жанры (из источника) |
| `actors` | string[] | Основной актёрский состав |
| `external_ids` | jsonb | `{kinopoisk_id, imdb_id, tmdb_id}` |
| `rating_external` | float | Рейтинг с источника (Kinopoisk/IMDb) |
| `added_at` | timestamp | Дата добавления в каталог |
| `watched_at` | timestamp, nullable | Дата просмотра (NULL — ещё не смотрели) |
| `watched_status` | enum | `not_watched` \| `watching` \| `watched` |
| `source` | enum | `telegram_text` \| `telegram_screenshot` \| `web_ui` |
| `added_by` | string | Telegram user id / имя пользователя |
| `notes` | text | Личные заметки (свободное поле) |

### 1.2 Классификация `category`

- `kids_series` — сериалы для детей
- `adult_series` — сериалы для взрослых
- `family_movie` — семейные фильмы
- `adult_movie` — фильмы для взрослых (в обычном смысле, не 18+)
- `cartoon` — мультфильм (детализация в `cartoon_subtype`)

### 1.3 Подкатегория мультфильмов `cartoon_subtype`

- `disney`
- `pixar`
- `soviet` — советские
- `russian` — российские
- `other` — остальные

> Примечание: категория и тип — не совсем ортогональны (`type=cartoon` почти всегда подразумевает `category=cartoon`, но технически сериал-мультфильм для детей может относиться и к `kids_series`, и одновременно иметь мультяшный подтип). Рекомендую в БД закрепить: `type` — техническая природа контента (фильм/сериал/мультфильм), `category` — как единственный тег полки, `cartoon_subtype` — только для мультфильмов. При добавлении LLM должен предлагать category и (если применимо) cartoon_subtype, а пользователь — подтверждать/менять в UI или в самом боте.

### 1.4 История поиска дублей (опционально, но полезно)

Таблица `match_candidates` — хранит кандидатов, найденных LLM при добавлении (на случай, если понадобится "показать, из чего выбирали").

## 2. Команды Telegram-бота

### Добавление контента
- `/add <название>` — найти фильм/сериал/мультфильм по названию и добавить (также работает без команды — просто отправка текста с названием воспринимается как `/add`)
- Отправка **скриншота** — бот распознаёт кадр/постер/текст на экране и ищет совпадение
- `/add_manual` — ручной ввод всех полей пошагово (на случай, если LLM ничего не нашёл)

### Управление списком
- `/list` — показать каталог (с пагинацией и инлайн-кнопками фильтров)
- `/list <категория>` — например `/list kids_series`
- `/find <текст>` — поиск по названию/актёрам внутри уже добавленного каталога
- `/delete <название>` — удалить из каталога (если совпадений несколько — уточняющие вопросы, как при добавлении)
- `/edit <название>` — изменить категорию/статус/заметку у существующей записи

### Просмотр / статус
- `/watched <название>` — отметить просмотренным (проставить `watched_at = now`)
- `/watching <название>` — отметить "смотрим сейчас" (для сериалов)
- `/unwatched <название>` — сбросить статус просмотра
- `/random` — предложить случайный непросмотренный фильм (можно с фильтром: `/random kids_series`)

### Статистика и сервис
- `/stats` — сводка: сколько всего, по категориям, сколько просмотрено
- `/help` — список команд
- `/cancel` — отменить текущий диалог уточнения (если бот задаёт вопросы, а пользователь передумал)

### Управление доступом
- `/adduser <telegram_id или @username>` — дать доступ к боту ещё одному пользователю (доступно любому, кто уже в whitelist)
- `/removeuser <telegram_id>` — убрать пользователя из whitelist
- `/users` — показать список пользователей с доступом

### Диалог уточнения (не команда, а сценарий)
Когда LLM находит несколько кандидатов по названию, бот присылает inline-кнопки вида:
```
Найдено несколько совпадений для "Гарри Поттер":
1) Гарри Поттер и философский камень (2001)
2) Гарри Поттер и узник Азкабана (2004)
...
Уточните год выпуска или выберите вариант ниже:
[Кнопка 1] [Кнопка 2] [Кнопка 3] [Это другое]
```
Если после выбора остаётся неоднозначность (например, найден и фильм, и сериал с похожим названием) — бот задаёт ещё один уточняющий вопрос (жанр/актёр/что именно — фильм или сериал), сформированный LLM динамически на основе реальных различий между кандидатами.

## 3. Дизайн сервиса (архитектура на VPS)

### 3.1 Компоненты

```
┌─────────────────┐      ┌──────────────────┐
│   Web UI (SPA)   │◄────►│                  │
│  (React/Vue)     │      │   Backend API    │      ┌──────────────┐
└─────────────────┘      │   (FastAPI/      │◄────►│  PostgreSQL  │
                          │    Node.js)      │      └──────────────┘
┌─────────────────┐      │                  │
│  Telegram Bot    │◄────►│                  │      ┌──────────────┐
│  (long polling / │      │                  │◄────►│  Файловое /   │
│   webhook)       │      └────────┬─────────┘      │  S3-хранилище │
└─────────────────┘               │                 │  постеров     │
                                    ▼                 └──────────────┘
                          ┌──────────────────┐
                          │  OpenAI API      │
                          │ (текст + vision  │
                          │  для распознавания│
                          │  скриншотов)      │
                          └────────┬─────────┘
                                    ▼
                          ┌──────────────────┐
                          │ Kinopoisk API /   │
                          │ TMDB API /        │
                          │ OMDb (IMDb data)  │
                          └──────────────────┘
```

### 3.2 Технологический стек (рекомендация)

- **Backend**: Python + FastAPI (асинхронный, удобен для LLM-интеграций) либо Node.js + NestJS
- **БД**: PostgreSQL (хорошо ложится на enum-поля, jsonb для внешних id, полнотекстовый поиск для `/find`)
- **Telegram-бот**: `aiogram` (Python) или `grammY`/`telegraf` (Node.js) — отдельный процесс, общается с backend через внутренний API или напрямую с той же БД через общий ORM-слой
- **Web UI**: React + Vite (SPA), можно проще — Next.js, если нужен SSR (не обязателен для внутреннего инструмента)
- **Хранилище постеров**: либо просто хранить ссылку на постер (проще всего, но зависит от доступности источника), либо скачивать и класть в S3-совместимое хранилище (MinIO на том же VPS) — рекомендую скачивать, чтобы не зависеть от протухания ссылок Kinopoisk/TMDB
- **Источники метаданных фильмов**:
  - **TMDB API** (themoviedb.org) — единственный источник метаданных на старте (Kinopoisk сознательно исключён — нет официального API, только нестабильные неофициальные обёртки)
  - **Перевод на русский**: TMDB поддерживает `language=ru-RU`, но покрытие неполное — особенно слабое для советских фильмов и нишевых тайтлов, где часто есть только английское (или вообще никакое) описание. Поэтому нужен шаг перевода:
    1. Backend запрашивает у TMDB данные с `language=ru-RU`
    2. Если `overview` на русском пустой или отсутствует — делается второй запрос с `language=en-US` (или без параметра — оригинальный язык), и **OpenAI переводит** описание на русский (обычный текстовый промпт-перевод, не vision)
    3. Аналогично для `title_ru` — если TMDB не отдаёт русское название, а только оригинальное, можно либо оставить оригинальное (для многих фильмов зрителю привычнее оригинал/устоявшийся русский перевод), либо попросить OpenAI предложить устоявшийся русский перевод названия (менее надёжно, годится как fallback с пометкой "предложено автоматически")
    4. Переведённый текст сохраняется в БД (`description`, `title_ru`), чтобы не переводить повторно при каждом просмотре
  - **OpenAI API** используется как: (1) экстрактор данных со скриншота (vision), (2) переводчик описаний с английского на русский, когда TMDB не отдаёт русский текст, (3) генератор уточняющих вопросов на основе списка кандидатов от TMDB, (4) классификатор category/cartoon_subtype
- **Reverse proxy / TLS**: Caddy или Nginx + Let's Encrypt
- **Деплой**: Docker Compose (backend, bot, postgres, minio, caddy — единым стеком), просто и предсказуемо для одного VPS
- **Аутентификация Web UI**: два пользователя, логин/пароль каждого задаются через `.env` (например `WEB_USER_1_LOGIN`, `WEB_USER_1_PASSWORD_HASH`, `WEB_USER_2_LOGIN`, `WEB_USER_2_PASSWORD_HASH`). Эти учётные записи никак не связаны с whitelist'ом Telegram-бота (`bot_users`) — это два полностью независимых механизма доступа к двум разным интерфейсам одного и того же каталога. JWT в httpOnly cookie после успешного логина, без регистрации через UI и без сброса пароля (при необходимости — руками поменять в `.env` и передеплоить)

### 3.3 Ключевые API-эндпоинты backend

```
GET    /api/media                — список с фильтрами (category, type, watched_status, query)
POST   /api/media                — создать запись
GET    /api/media/{id}
PATCH  /api/media/{id}
DELETE /api/media/{id}
GET    /api/media/random
GET    /api/stats

POST   /api/resolve              — вход: текст названия, выход: кандидаты (для бота и веб-формы добавления)
POST   /api/resolve/screenshot   — вход: изображение, выход: кандидаты
```

Telegram-бот и Web UI работают через один и тот же backend API — так классификация и логика поиска дублей не дублируются в двух местах.

### 3.4 Доступ нескольких пользователей к единой базе

Каталог один общий для всех, изолированных пользовательских списков не нужно. Но бота не должны использовать посторонние. Решение — **whitelist в БД, управляемый прямо из бота**, без передеплоя:

- Таблица `bot_users`: `telegram_id` (pk), `display_name`, `added_by_telegram_id`, `added_at`
- **Bootstrap**: первый пользователь задаётся через env-переменную `INITIAL_ADMIN_TELEGRAM_ID`. При старте бот проверяет, пуста ли таблица `bot_users` — если пуста, автоматически добавляет туда пользователя с этим ID. Дальше все проверки идут только по таблице, а не по env
- Любой пользователь из whitelist может добавить нового командой `/adduser <telegram_id или @username>` — бот сразу вносит запись в `bot_users`, перезапуск не требуется
- Команда `/removeuser <telegram_id>` — убрать пользователя из whitelist (важно не дать удалить самого себя последним, чтобы не остаться без доступа — либо разрешить, раз bootstrap всегда можно повторить через env при пустой таблице)
- Команда `/users` — показать текущий список пользователей с доступом
- Middleware в aiogram на каждый апдейт проверяет наличие `telegram_id` отправителя в `bot_users` (с кэшированием на несколько секунд/минут, чтобы не бить БД на каждое сообщение); для не-whitelisted — сообщение "нет доступа, попросите добавить вас через /adduser у того, кто уже пользуется ботом"
- Все пользователи в whitelist равноправны — нет отдельной роли "админ" сверх этого; можно добавить в будущем, но для MVP не нужно
- Поле `added_by` в таблице `media` продолжает фиксировать, кто из пользователей добавил конкретную запись (для истории, не для разграничения доступа)

### 3.5 Поток добавления фильма через бота (детально)

1. Пользователь отправляет текст или скриншот
2. Если скриншот → OpenAI Vision извлекает предполагаемое название/год/другие подсказки
3. Backend запрашивает TMDB по названию (`language=ru-RU`) → получает список кандидатов
4. Если кандидат один и явно точное совпадение → backend проверяет, есть ли русское описание; если нет — делает повторный запрос TMDB на английском и просит OpenAI перевести описание → backend определяет `category`/`cartoon_subtype` (эвристика + запрос к LLM: "это детский или взрослый сериал / disney/pixar/советский мультфильм?") → бот показывает карточку с постером на подтверждение
5. Если кандидатов несколько → OpenAI генерирует уточняющий вопрос на основе реальных различий между кандидатами (год, жанр, актёры) → бот присылает inline-кнопки
6. После подтверждения — запись сохраняется, постер скачивается в хранилище, статус `added_at = now`, `watched_status = not_watched`

## 4. Промпт для Claude Code

Скопируйте текст ниже целиком в Claude Code — это техническое задание для разработки MVP.

```
Разработай MVP веб-сервиса для каталогизации фильмов/сериалов/мультфильмов с управлением через Telegram-бота и веб-интерфейс. Проект разворачивается на одном VPS через Docker Compose.

СТЕК:
- Backend: Python 3.12 + FastAPI + SQLAlchemy (async) + Alembic для миграций
- БД: PostgreSQL 16
- Telegram-бот: aiogram 3.x, отдельный сервис, общается с backend только через HTTP API (никакого прямого доступа к БД из бота)
- Web UI: React + Vite + TypeScript, простой и функциональный дизайн (без излишеств), Tailwind CSS
- Хранилище постеров: MinIO (S3-совместимое), backend скачивает постер из TMDB и кладёт в MinIO, в БД хранится внутренний URL
- Reverse proxy: Caddy с автоматическим TLS
- Всё оборачивается в docker-compose.yml с сервисами: backend, bot, web, postgres, minio, caddy

МОДЕЛЬ ДАННЫХ (таблица media):
- id (uuid, pk)
- title (string), title_ru (string, nullable)
- year (int)
- description (text)
- poster_url (string) — внутренняя ссылка на MinIO
- type (enum: movie, cartoon, series)
- category (enum: kids_series, adult_series, family_movie, adult_movie, cartoon)
- cartoon_subtype (enum, nullable: disney, pixar, soviet, russian, other)
- genres (string[])
- actors (string[])
- external_ids (jsonb) — tmdb_id, imdb_id, kinopoisk_id
- rating_external (float, nullable)
- added_at (timestamp)
- watched_at (timestamp, nullable)
- watched_status (enum: not_watched, watching, watched)
- source (enum: telegram_text, telegram_screenshot, web_ui)
- added_by (string)
- notes (text, nullable)

ИНТЕГРАЦИИ:
- TMDB API (https://www.themoviedb.org/documentation/api) — единственный источник поиска фильмов/сериалов по названию, получения постеров, описаний, года, жанров, актёров. Kinopoisk не используется (нет официального API). Запрашивай с language=ru-RU.
- Перевод описаний: если TMDB не возвращает русский overview (пустая строка) — делай повторный запрос TMDB с language=en-US (или original_language), затем переводи overview на русский через OpenAI (обычный текстовый completion-запрос, чёткий системный промпт "переведи на русский, сохрани стиль синопсиса, без добавления отсебятины"). Сохраняй переведённый текст в БД, чтобы не переводить повторно.
- OpenAI API (chat completions + vision) используется для:
  1. Распознавания текста/названия на скриншоте, присланном в бот (vision-запрос)
  2. Перевода описания на русский, когда TMDB не отдаёт русский overview
  3. Классификации найденного медиа по category/cartoon_subtype на основе жанров, описания и страны производства (структурированный JSON-ответ)
  4. Генерации уточняющего вопроса для пользователя, когда TMDB вернул несколько кандидатов — вопрос должен быть основан на реальных различиях между кандидатами (разные годы, разные жанры, фильм vs сериал и т.д.)
  Все промпты к OpenAI должны требовать строго JSON-ответ без markdown-разметки, чтобы результат парсился напрямую (кроме перевода — там просто текст).

BACKEND API ЭНДПОИНТЫ:
- GET /api/media — список с query-параметрами: category, type, cartoon_subtype, watched_status, search, page, page_size
- POST /api/media — создать запись
- GET /api/media/{id}
- PATCH /api/media/{id}

/random [категория]
/stats

Диалоговая логика бота:
- Хранить состояние диалога через aiogram FSM (Finite State Machine)
- При множественных кандидатах — показывать inline-кнопки с вариантами (название + год), плюс кнопка "Это другое" для перехода к ручному вводу
- Если после выбора кандидата всё ещё неоднозначность в классификации (например определить kids_series vs adult_series) — бот присылает вопрос с кнопками-вариантами категорий

Доступ нескольких пользователей (без передеплоя):
- База фильмов общая — никакой изоляции по пользователям
```

## 5. Принятые решения

- ✅ Kinopoisk на старте не используется — единственный источник TMDB, с переводом описаний через OpenAI там, где TMDB не даёт русский текст
- ✅ Пользователей бота несколько, база фильмов одна общая
- ✅ Whitelist пользователей бота хранится в БД (таблица `bot_users`), а не в env — любой пользователь из списка может добавить другого командой `/adduser` без перезапуска бота. Первый пользователь задаётся через `INITIAL_ADMIN_TELEGRAM_ID` в `.env` и попадает в таблицу автоматически при первом старте
- ✅ Web UI использует двух независимых пользователей с логином/паролем, заданными через `.env` — эти учётные записи никак не связаны с whitelist'ом Telegram-бота
